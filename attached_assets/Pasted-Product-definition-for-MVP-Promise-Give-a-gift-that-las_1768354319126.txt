Product definition for MVP

Promise: Give a gift that lasts. In under 60 seconds, a contribution becomes real ownership inside a recipient’s fund.

MVP shape:

Owner app (mobile): parents, guardians, and adults managing their own funds.

Giver flow (web): no app, no account. Link or QR, pay, done.

Brokerage: embedded account creation inside onboarding (or just-in-time before first investment). The owner never “connects” a broker manually.

Core objects (keep the mental model tight):

Household (you)

Fund (Ari’s Future Fund)

Event page (Bar Mitzvah 2026, Birthday, Graduation)
Events are just branded pages that point to a Fund and change copy, theme, goal, and suggested amounts.

Gift (a contribution)
A gift always maps to: fund + optional event + message + payment + investment action.

The simplest user journeys (all MVP-critical)
Journey A: Parent creates a fund, then an event, shares link

Create account (email + passkey)

Create Fund (name + photo + “for who”)

Create Event page (template + goal + suggested amounts)

Share link or show QR

See gifts arrive in Activity

Send thank-yous

Journey B: Giver sends a gift in 45 seconds

Open link

Choose amount

Confirm “Future Fund” (default) or optionally “Pick a stock”

Add note + name

Apple Pay

Card reveal + shareable receipt

Journey C: First-time investing setup (KYC) happens once

Triggered:

during onboarding (recommended if you want “this is real” trust)

OR just-in-time when owner creates first fund (best balance)

OR just-in-time when first gift arrives (highest conversion, but awkward)

MVP recommendation: KYC when creating first Fund, with a “Finish later” that still lets them build pages, but clearly labels “Investing not active yet.”

The “activation moment” metric

The equivalent of “7 friends in 10 days” should be behavior that predicts retention.

Best candidate:
Within 7 days:

Create 1 Fund

Create 1 Event page

Receive 1 completed gift

Secondary:

Send 3 thank-yous (correlates with repeat giving)

Design the product to drive this sequence.

Motion and animation
Principles

Confirm, don’t entertain. Motion exists to show “what just happened” and “what happens next.”

Fast and quiet. 150–250ms for UI transitions. 300–450ms max for “card reveal” moments.

Never block checkout. Animation must not delay Apple Pay.

Where motion matters (MVP)

Card reveal (giver)

A single “card flip” with a soft light sweep.

Ends with two clear CTAs: “Text this card” and “View receipt.”

Progress bar fill (owner)

When a gift settles: progress bar fills, then stops. No looping.

Status chips

Pending → Active: chip morphs and changes label.

If there is a delay, show a “Why?” drawer.

Fund total update

Number tick-up (subtle), not a casino vibe.

Navigation

Standard iOS/Android transitions, no custom page swooshes.

Micro-interactions (high trust)

Haptic on “Gift sent”

A single checkmark animation on completion

Skeleton loaders for balances and activity while data loads

Icon system
Style

Simple outline icons (2px stroke), rounded corners, minimal detail.

Avoid “fintech” clichés (candlesticks, rockets, coins).

Prefer “registry” and “receipt” metaphors: card, ribbon, check, shield, lock, leaf.

Core icons you need

Fund (leaf or simple circle mark)

Event (ticket or tag)

Gift (card)

Receipt (document + check)

Privacy (lock)

Trust (shield)

Help (question)

Share (standard share icon)

Status: pending (clock), active (check), needs action (alert)

Placement rules

Icons should clarify labels, not replace them.

In primary flows, use icons only in headers and rows. Never on critical buttons without text.

Brand system
Brand personality

Calm, premium, modern registry.

Warm but not cute.

Confident and simple.

Tone rules

Speak like a great concierge.

Use plain words: “gift,” “fund,” “invested,” “receipt.”

Avoid finance jargon in primary UI. Keep it in drawers.

Visual direction

Lots of whitespace

Large type for totals, small type for legal

Soft corners

One accent color used sparingly for primary actions and status “Active”

Mascot (optional, and only if done right)

A mascot can destroy trust if it feels childish. If you do it, keep it abstract.

Best option

A minimal “leaf mark” character used as a helper, not a personality.

No face by default. No speaking in jokes.

Shows up only in:

empty states (“No gifts yet”)

gentle guidance (“Finish setup to activate investing”)

Alternate (even safer)

No mascot at all. Use “card” as the hero artifact instead.

Based on what typically breaks clarity in products like this:

Missing visible account status states (pending vs active)

“Fund vs Event vs Account” not defined clearly in UI

Not enough receipts and status explanations

Too many settings too early
